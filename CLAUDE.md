# CLAUDE.md

## Project

**fooWeapons** — Paper 1.21.11 plugin + companion resource pack that adds custom firearms playable on vanilla Java 1.21.11 clients (no client mod required). Original work, not derived from any existing mod.

Deployment target: Greg's GPortal-hosted Paper 1.21.11 server.

## Stack

- **Language:** Java 21 (required by Paper 1.21.x).
- **Server platform:** Paper 1.21.11.
- **Build:** Gradle (Kotlin DSL); wrapper at `./gradlew` / `.\gradlew.bat`.
- **Plugin API:** `io.papermc.paper:paper-api:1.21.11-R0.1-SNAPSHOT` (`compileOnly` for main, `testImplementation` for tests).
- **Test:** JUnit 6 for pure-logic tests; MockBukkit 4.x (org.mockbukkit.mockbukkit:mockbukkit-v1.21) for Bukkit-touching tests.
- **YAML parsing:** SnakeYAML, provided transitively by Paper at runtime and by paper-api/MockBukkit at test runtime.

## Architecture

- Plugin and resource pack are **two artifacts in one project**. Their only contract is the set of `(weapon_id, custom_model_data integer)` pairs.
- Weapons are defined in YAML (`plugin/src/main/resources/weapons/`). `WeaponLoader` parses them into immutable `Weapon` records, stored in `WeaponRegistry` keyed by ID.
- Weapon items are vanilla `CROSSBOW` ItemStacks with `CustomModelData` set, plus PDC tags for `weapon_id`, `ammo`, and `last_fired_ms`. The resource pack overrides `minecraft:crossbow` to render `fooweapons:item/<id>` when CMD matches.
- Per-item runtime state (current ammo, last-fired timestamp) lives on the ItemStack's PDC via `ItemState` — survives drops, deaths, and chest storage.

## Development

```bash
./gradlew :plugin:test     # Run pure-logic JUnit suite
./gradlew :plugin:jar      # Build the plugin jar only
./gradlew dist             # Build both artifacts and print their paths
```

Build outputs:
- Plugin jar: `plugin/build/libs/nf_fooweapons-0.1.0.jar`
- Resource pack zip: `build/dist/fooWeapons-resourcepack-0.1.0.zip`

The texture generator only needs to run if textures change:
```bash
python tools/generate_textures.py     # requires `pip install Pillow`
```

## Branching workflow

Three-branch model:

| Branch | Role |
|---|---|
| `dev` | Active work; all commits land here first. |
| `beta` | Pre-release testing; only promoted on explicit request from Greg. |
| `release` | Stable; **GitHub default branch**; only promoted on explicit request from Greg. |

Promotions are explicit, never automatic. On "push to beta": merge dev→beta, push, build, attach jar to a GitHub pre-release. On "push to release": merge beta→release, push, build, create or update a tagged release with the jar and resource pack zip.

## Conventions

- **MVP scope discipline.** v0.1.0 is intentionally narrow (pistol only, semi-auto, no ADS / recoil / auto-fire / fire-mode toggle / consumable mags / config). Don't add Plan 2 features without explicit go.
- **Vanilla client only.** No client mod required, by design. If a feature would require a Fabric/Forge companion mod, flag it; don't quietly add one.
- **Original work.** No reproduction of code, models, textures, or designs from existing mods (e.g. Vic's Modern Warfare). Models are hand-designed blocky cuboid silhouettes; textures are procedurally generated.
- **TDD for pure logic.** Code that doesn't touch Bukkit (math, parsing, cooldown checks) is test-first with JUnit. Code that needs a Bukkit runtime is exercised via manual smoke test.
- **Single descriptor: `plugin.yml` only.** Do NOT add `paper-plugin.yml` — the two conflict and break loading on Paper. We have no `PluginBootstrap`/`PluginLoader` features, so the legacy descriptor is sufficient.
- **Verify version-specific facts via WebSearch** before asserting them (current Paper version, pack_format value, library compatibility, etc.). Training-data memory is stale.
